# Forest density benchmark — implementation awaiting local validation

`ForestPreview.tscn` adds a bounded pine-forest area to `WORLD/Scenes/test.tscn`. It extends the existing 16-tree preview in the walking direction, without modifying it. Default footprint: an ellipse centred roughly (18, -118) m from spawn, radii 82 × 86 m. The preview produces up to 115 deterministic tree sites. Their spacing grows from a nominal 7.5 m in the inner grove to 14 m around the edges; acceptance frequency also decreases outward. A 3 m half-width winding gap makes it easier to walk through. It reserves 8 m around the original 16 authored trees. A patch can feel denser near its heart without having one perfect ring or grid.

This first benchmark reuses `ASSETS/Vegetation/Trees/PineTree002/PineTree002.tscn` only: existing 70/280 m authored LOD1/LOD2 switching, randomized yaw, 0.82–1.33 scale, and native renderer culling. Both LOD meshes stay loaded per instance, so it is **not** draw-call batching or global tree streaming. The existing firs, four authored pines, bermuda grass and meadow grass remain unchanged. The natural grass scatter continues around the player but the special meadow clumps are still tied to the original 16 authored trees. No collision, tree interaction, forest-wide meadow allocation or wind is added.

The layout is computed once from a fixed seed with capped CPU attempts; O(N²) spacing checks happen only at startup for at most 250 preview trees, not on game frames. Native terrain surface queries are limited to four per physics tick, only for positions within 140 m of the player. Unloaded positions back off 2 seconds and can retry up to 18 times before being skipped. A single 0.6 s timer checks pending spots while travelling; when all trees have been placed or skipped, it stops and physics processing stays disabled. Native per-tree visual LOD still runs in the renderer. The F1 toggle under OTHER MODELS (`Visible: ForestPreview`) hides the entire new grove and suspends active placement. The original 16 trees have their existing F1 controls.

Performance caution: 115 additional detailed pines may be expensive on older GPUs, especially with alpha cutouts, shadows and 60 FPS cap enabled. Only near-range LOD1 trees cast shadows; distant LOD2 shadows are off. Tune `Configuration/ForestMaster.tres` TreeCount downward and NearShadows=false if the test frame times increase. When scaling to many hundreds/thousands, replace this bounded node-per-tree trial with spatial forest streaming / per-tile MultiMesh batches and LOD/impostors.

Local test: pull main, build Godot .NET, run test.tscn. Walk forward through the preview group toward negative Z into the grove; note open entry, thickening central pine canopy, occasional narrow path, and thinning opposite edge. Watch `Forest: placed/planned` in top-left: spots outside the collision-loaded radius will appear as you approach, and steep slopes are skipped. Toggle F1 → OTHER MODELS → Visible: ForestPreview to compare performance at the same camera position, and use F2 frame graph. Verify F4 respawn does not duplicate trees, root alignment, shadows, LOD transitions, visible collision-loading pop-in and how the density reads from player eye level. Validate with cap off if comparing frame cost. Source/resource checks were performed; no full engine build or visual performance acceptance was possible here.
