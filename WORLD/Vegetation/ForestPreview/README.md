# Forest density benchmark — implementation awaiting local validation

`ForestPreview.tscn` adds a bounded pine-forest area to `WORLD/Scenes/test.tscn`. It lies on the flatter side of spawn opposite the uphill existing 16-tree preview, without modifying those trees. Default footprint: an ellipse centred roughly (18, +118) m from spawn, radii 82 × 86 m (positive Z, away from the mountain shoulder). The preview produces up to 115 deterministic tree sites. Their spacing grows from a nominal 7.5 m in the inner grove to 14 m around the edges; acceptance frequency also decreases outward. A 3 m half-width winding gap makes it easier to walk through. It reserves 8 m around the original 16 authored trees. A patch can feel denser near its heart without having one perfect ring or grid.

This first benchmark reuses `ASSETS/Vegetation/Trees/PineTree002/PineTree002.tscn` only: existing 70/280 m authored LOD1/LOD2 switching, randomized yaw, 0.82–1.33 scale, and native renderer culling. Both LOD meshes stay loaded per instance, so it is **not** draw-call batching or global tree streaming. The existing firs, four authored pines, bermuda grass and meadow grass remain unchanged. The natural grass scatter continues around the player but the special meadow clumps are still tied to the original 16 authored trees. No collision, tree interaction, forest-wide meadow allocation or wind is added.

The layout is computed once from a fixed seed with capped CPU attempts; O(N²) spacing checks happen only at startup for at most 250 preview trees, not on game frames. Native terrain surface queries are limited to four per physics tick, only for positions within 140 m of the player. Unloaded positions back off 2 seconds without being permanently discarded while distant. Only positions within 35 m of the player can be abandoned after 18 unsuccessful probes, avoiding silent loss of the deeper forest while standing at spawn. A single 0.6 s timer checks pending spots while travelling; when all trees have been placed or skipped, it stops and physics processing stays disabled. Native per-tree visual LOD still runs in the renderer. The F1 toggle under OTHER MODELS (`Visible: ForestPreview`) hides the entire new grove and suspends active placement. The original 16 trees have their existing F1 controls.

Performance caution: 115 additional detailed pines may be expensive on older GPUs, especially with alpha cutouts, shadows and 60 FPS cap enabled. Only near-range LOD1 trees cast shadows; distant LOD2 shadows are off. Tune `Configuration/ForestMaster.tres` TreeCount downward and NearShadows=false if the test frame times increase. When scaling to many hundreds/thousands, replace this bounded node-per-tree trial with spatial forest streaming / per-tile MultiMesh batches and LOD/impostors.

Local test: pull main, build Godot .NET, run test.tscn. Turn away from the original uphill preview trees and walk toward positive Z into the flat-side grove; note the sparse entry, thickening central pine canopy, winding open gap, and thinning opposite edge. Watch `Forest: placed/planned` in top-left: spots outside the collision-loaded radius will appear as you approach, and steep slopes are skipped. Toggle F1 → OTHER MODELS → Visible: ForestPreview to compare performance at the same camera position, and use F2 frame graph. Verify F4 respawn does not duplicate trees, root alignment, shadows, LOD transitions, visible collision-loading pop-in and how the density reads from player eye level. Validate with cap off if comparing frame cost. Source/resource checks were performed; no full engine build or visual performance acceptance was possible here.

## Trunk collision enabled — awaiting local validation

Trees now opt into the shared PHYSICS/StaticCollision construction. PineTree002.tscn carries one StaticCollisionInstance outside both visual LODs; its shared capsule is radius 0.32 m, height 16 m, centred 8 m above the asset origin. The original twelve firs now use A/B/C wrapper scenes with one shared radius 0.14 m / height 3.5 m capsule. Their wrappers cancel the existing B/C display offsets before grounding. These are deliberately simple blocking proxies, not anatomically exact trunk geometry; review their fit locally.

All four original pines and the forest's PineTree002 instances inherit collision from the same asset prefab. No duplicate collider per LOD, full-canopy hull, per-tree ray or tick was added. Layer 4 / mask 0 preserves player contact and terrain-only placement queries. Shape resources are shared; bodies are per tree. Hiding/culling visuals does not disable collision; actual parent unload frees the body. Existing finite resident-world limitation remains.

Local: build, run test.tscn, enable Debug → Visible Collision Shapes, approach pine/fir trunks from several angles, walk through foliage gaps and inspect scaled/rotated instances. Check B/C roots align, F4 doesn't duplicate bodies, changing LOD keeps the same collision and boulders/grass still ground on terrain. Disable an asset profile with Mode None and restart to opt out. Source references/scene layout reviewed; compilation, contact fit and FPS remain unverified here.

## Dark pine replacement and tall variants — awaiting local validation

The stable PineTree002.tscn now points both authored LODs at the pushed PineTree002_Fix exports, preserving its 70/280 m native ranges, shared trunk capsule and original four preview instances. The original model files stay available but are not used by that wrapper.

ForestMaster now supplies PineTree003.tscn and TallTreeCount = 8. At layout generation, the nearest eight planned sites to spawn are marked tall; no new RNG draws or placement sites are introduced. The forest remains 115 planned trees, with the original spacing/path/grass and boulder reservations unchanged. If fewer valid tall sites can ground, fewer will appear. Existing shadow handling applies equally to both variants.

PineTree003 source bounds span about 28.84 m, with foliage starting around 10 m. Its LOD1/LOD2 have 23,002/6,780 triangles, cutout needles, matching pivots and shared texture URIs. Its own capsule profile is radius 0.34 m, height 21 m; placement scale affects both visuals and collision. It uses the same native 70/280 m ranges and a single collider outside both visual LODs.
